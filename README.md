# GraphRAG Papers — код-ревью

Локальный сервис ответов по английским аннотациям arXiv. Сначала он находит статьи, затем добавляет извлечённые из них связи и передаёт контекст Qwen. Это RAG с графовым обогащением, а не поиск новых статей по графу.

**На ревью ничего не запускай.** Открой код и [сохранённые результаты](RESULTS_RU.md). Для репетиции: [план подготовки](PREP_RU.md), [короткие ответы](QUESTIONS_RU.md) и [подробный разбор вопросов по коду](CODE_QUESTIONS_DETAILED_RU.md).

## Отдельно: подготовка локальной базы

Нужны Python 3.12+, `uv`, Neo4j с поддержкой векторных индексов и Ollama. В `data/` уже есть корпус и тройки, получать их заново не обязательно. Подготовка меняет БД: используй отдельную локальную базу.

```bash
uv sync
cp .env.example .env
# Впиши пароль своей локальной Neo4j в .env, затем:
set -a
. ./.env
set +a
ollama pull qwen2.5:7b-instruct-q4_K_M
uv run python code/load_graph.py
uv run python code/add_abstracts.py
uv run python code/embeddings.py
```

Для API дождись `ONLINE` у индекса `paper_vec`, затем `uv run uvicorn --app-dir code app:app`. Сервер только для локальной работы: в API нет аутентификации. Для нового эксперимента — `uv run python code/eval_graph.py`; отчёт пишется в `data/evaluations/graph_eval.json`, существующий файл не перезаписывается.

Только если нужен **новый корпус**, `code/fetch_papers.py` перезаписывает `data/papers.json`, а `code/extraction.py` дописывает новые ID в `data/triplets.jsonl`. Не смешивай разные версии корпуса в одной базе.

Исходники схем — `.puml` в `diagrams/`; SVG рядом открываются офлайн. Проект учебный, помощь ИИ использовалась при разработке и оценке. Права на тексты arXiv остаются у правообладателей.
