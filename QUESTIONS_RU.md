# Все вопросы к код-ревью — с примерами

Читай блоками. На репетиции отвечай сначала **одним предложением**, затем приводи пример. В каждом разделе первой идёт короткая версия, ниже — то, что нужно понимать, если спросят «почему?». Это разбор кода **этой** папки.

## 1. Данные: от arXiv до Neo4j

### Что за корпус, почему `cs.CL` и почему только аннотации?

**Корпус — тексты, по которым отвечает система.** `cs.CL` — категория arXiv *Computation and Language*: языковые модели, NLP, поиск и смежные задачи. Она подходит по тематике и ограничивает объём. Сборщик берёт до 500 свежих на момент запроса записей и отбрасывает слишком короткие аннотации. В сохранённом `papers.json` 500 статей; у 498 уникальных ID есть запись извлечения. Это не специально отобранные «лучшие статьи про RAG». Аннотации приходят в одном формате, поэтому PDF не разбираются. Если ответ есть только в полном тексте, система его не увидит.

| Файл | Что берёт | Что отдаёт или записывает |
|---|---|---|
| [`fetch_papers.py`](code/fetch_papers.py) | arXiv Atom API | [`papers.json`](data/papers.json): `id`, `title`, `abstract` |
| [`extraction.py`](code/extraction.py) и [`extract_triplets.py`](code/extract_triplets.py) | `paper['abstract']` и инструкция о формате | [`triplets.jsonl`](data/triplets.jsonl): одна JSON-запись на строку, с `paper_id`, `title`, `entities`, `relations` |
| [`load_graph.py`](code/load_graph.py) | `triplets.jsonl` | `Paper`, `Entity`, `MENTIONS`, `R`, `source_ids` в Neo4j |
| [`add_abstracts.py`](code/add_abstracts.py) | `papers.json` и уже существующие `Paper` | `Paper.abstract`; новые статьи не создаёт |
| [`embeddings.py`](code/embeddings.py) | Заголовки и аннотации | `Paper.embedding` и индекс `paper_vec` |

### Кто придумал `Entity`, `head`, `relation`, `tail`? Что проверяет Python?

**Ты задал формат и список типов связей. Qwen предложила конкретные имена и стрелки по аннотации.** Например, из «Method A uses Encoder B» модель может вернуть `entities: ['Method A', 'Encoder B']` и тройку `head: 'Method A', relation: 'USES', tail: 'Encoder B'`. `head` — начало стрелки, `tail` — конец. В другой порядок их переставлять нельзя: это уже другое утверждение.

`validate_triplets` отбрасывает связь, если нет одного из концов или конец не входит в `entities`. Неизвестный тип заменяет на `RELATED_TO`. Затем оставляет только сущности, участвующие в связях. Проверка формата **не доказывает смысл**. У настоящего `RAG-FGO` (найди `2611.17788v1` в обоих файлах данных) тройка говорит `RAG-FGO -IMPROVES-> ELITE_PRESERVING_MEMORY_POOL`, а аннотация — что метод **вводит** пул. Это пример ошибки экстрактора, а не правильная связь.

### Что именно загружает `load_graph.py`? Зачем `MERGE` и что с `entity_names.py`?

**Загрузчик не запускает модель: он превращает готовые записи в узлы и рёбра.** По ID находит или создаёт `Paper`, по имени — `Entity`. `MERGE` находит существующий шаблон или создаёт его, а ограничения уникальности защищают ID статьи и имя сущности. `MENTIONS` соединяет статью с сущностью; направленное `R` соединяет две сущности, смысловой тип (`USES`, `EXTENDS`) лежит в `r.type`. `source_ids` хранит ID статей, из которых извлекли именно это ребро; один ID не добавляется дважды. Записи одной статьи выполняются отдельными транзакциями: при сбое возможна частичная загрузка.

В версии для показа нет `entity_names.py`: одно правило `ACTGCG → ActGCG` записано в самом загрузчике. Оно работает и для имён узлов, и для обоих концов ребра; иначе один метод мог бы получить два узла. Это **явный алиас, не эвристика слияния всех похожих слов**.

### Зачем отдельно `add_abstracts.py` и `embeddings.py`?

**Текст нужен генератору, вектор — поиску.** `add_abstracts` по ID дописывает исходную аннотацию в Neo4j. `embed_papers` кодирует заголовок и аннотацию через MiniLM и пишет вектор. Индекс `paper_vec` помогает найти близкие векторы. Размер 384 — число компонент вектора, не число токенов текста; у MiniLM вход обычно ограничен 256 токенами. При построении промпта берётся полная сохранённая аннотация.

## 2. API: Pydantic, `lifespan` и подключение

### Почему две модели Pydantic, а не одна или `dict`?

**Запрос и ответ имеют разные обязательные поля.** Клиент отправляет `{"question":"..."}`, сервер возвращает `{"question":"...","answer":"..."}`. Одна модель с обязательным `answer` потребовала бы ответ от клиента. Необязательный `answer` скрыл бы гарантию ответа сервера. С обычным `dict` пришлось бы самим проверять поля и типы. FastAPI с Pydantic валидирует вход, отдаёт 422 при отсутствии `question` и показывает схемы в `/docs`. Пустая строка пока допустима: `str` не проверяет длину.

### Что значит `lifespan=lifespan`, что передаётся и откуда берётся `app`?

**Слева — имя параметра FastAPI; справа — передаваемая функция.** Если назвать её `manage_resources`, будет `FastAPI(lifespan=manage_resources)`. Справа нет `()`, потому что мы не вызываем её при импорте. FastAPI вызывает её на старте и сам передаёт приложение в `lifespan(app)`.

### Что за `@asynccontextmanager`, зачем `async`, а когда идёт код после `yield`?

**Декоратор, не аргумент.** Он превращает асинхронную функцию с `yield` в функцию, которую FastAPI может использовать в `async with`. Две части разделяет **`yield`, не `async`**:

```python
async with lifespan(app):  # при входе выполнить код до yield
    ...                    # сервер обслуживает запросы
# при выходе сервер завершает lifespan; внутренний with закрывает драйвер
```

Обычный `def` с `yield` создаёт генератор, который продвигают `next()`. `async def` с `yield` создаёт асинхронный генератор, который продвигают `await anext()`. Декоратор делает эти шаги вместо нас. Можно написать класс с `__aenter__` и `__aexit__`, но декоратор компактнее. `async` здесь для интерфейса FastAPI, а не ускорения: Neo4j и загрузка модели синхронные. При штатной остановке, а также при ошибке загрузки MiniLM, внутренний `with` закрывает уже открытый драйвер. Это происходит не после каждого вопроса.

### Для чего `verify_connectivity`, `app.state` и `/health`?

**Создать объект драйвера — не значит подключиться.** `verify_connectivity()` даёт ошибку уже на старте, если Neo4j недоступен или пароль не подходит. Не проверяет наличие статей, готовность `paper_vec` и доступность Ollama. `app.state` хранит общие драйвер и модель; `with driver.session()` в QA открывает короткую сессию для запросов и закрывает сессию, **не** драйвер. `/health` лишь подтверждает, что HTTP-приложение отвечает. Пароль берётся из окружения; `.env.example` — шаблон, Python сам `.env` не подхватывает.

## 3. Поиск: `retrieval.py`

### Зачем `GENERIC_TERMS` и `extract_title_terms`?

**Нужны имена методов, а не любые слова из вопроса.** Для `How does RAG-FGO improve RAG?` регулярка выделит `How`, `does`, `RAG-FGO`, `improve`, `RAG`, сохранив дефис внутри. `RAG-FGO` похоже на имя: дефис или `_`, либо минимум две заглавные буквы. `RAG` тоже проходит по заглавным, но есть в `GENERIC_TERMS` и отбрасывается как слишком общее. Получаем `['rag-fgo']`. Слова вроде `fine-tuning` тоже исключены, хотя имеют дефис. Повторы удаляются, берётся не более десяти. Если список пуст, второго запроса нет. Это эвристика: `Bioformer` без дефиса и второй заглавной она может не распознать.

### Для чего `title_pattern`? Что значат `split`, `\b`, `(?is)` и `escape`?

**Название должно совпасть даже с другим разделителем и регистром.** `split` делит `rag-fgo` на `rag` и `fgo`. `join` ставит между ними `[\W_]+`: это один или несколько разделителей, например дефис, пробел или `_`. Поэтому `RAG-FGO`, `RAG FGO`, `rag_fgo` подходят. `\b` — граница слова, поэтому `RAG-FGO2` не подходит; `.*` разрешает остальной заголовок; `(?is)` игнорирует регистр и разрешает `.` захватывать перенос строки; `re.escape` заставляет искать части буквально. Функция **строит шаблон**, а Neo4j проверяет им заголовки.

### Как работает `candidates = {row['id']: {**row, 'matched_names': []} ...}`?

**Это словарь по ID статьи, а не список.** В обычном цикле было бы так:

```python
candidates = {}
for row in vector_hits:
    article = dict(row)
    article['matched_names'] = []
    candidates[row['id']] = article
```

`**row` переносит поля в новый словарь. Затем `title_hits` записываются тоже по ID: совпавший ID заменит старую запись, новый ID добавится. Так дубли не занимают два места, а статья из второго поиска может попасть в результат, даже если её не было в векторном топе.

### Почему статья с баллом 0.68 может быть выше статьи с 0.90?

**Совпадение названия важнее балла.** `sorted` сравнивает ключи по возрастанию слева направо. У A без совпадения ключ `(0, -0.90, 'A')`, у B с одним совпадением `(-1, -0.68, 'B')`. `-1 < 0`, поэтому B первая. Если число совпадений одинаковое, выше больший `score`; при равенстве сравниваются ID. `[:k]` оставляет до трёх. `score` — близость по векторам, не вероятность правильного ответа. `k=3` — инженерный предел для прототипа, не доказанный оптимум.

## 4. Связи, промпт и генерация: `qa.py`

### Что мы передаём как статью, а что как графовый факт?

**Статья — URL, заголовок и полная аннотация. Факт — короткая извлечённая связь с источником.** Например: `Method A -USES-> Encoder B (sources: URL)`. В режиме без графа остаются те же вопрос и статьи, просто `facts=[]`. Граф не добавляет новых статей и не делает многошаговый поиск. Neo4j используется даже без фактов, потому что там хранится векторный индекс.

### Что делают `graph_context`, `source_ids`, `coalesce` и `LIMIT 30`?

**Берём связь только из найденной статьи, которая указана источником конкретного ребра.** Допустим, статья №1 упоминает A, но `A USES B` извлекли из статьи №2. Если нашли только №1, ребро не попадёт в промпт. `MENTIONS` означает «упоминает», `source_ids` — «извлечено из».

`coalesce(r.source_ids, [])` возвращает первое не `null` значение: список источников или `[]`, если свойства нет. В пустом списке ID не найдётся. `collect(DISTINCT p.id)` собирает уникальные ID выбранных источников для тройки. `LIMIT 30` — максимум 30 троек на **весь** запрос; перед обрезкой они сортируются по именам и типу, не по полезности для вопроса. Это предел размера контекста, а не измеренная лучшая настройка.

### Почему убрали `use_graph`? Для чего звёздочка и что делает `A if flag else B`?

**HTTP-режим всегда использовал граф, отдельный переключатель в QA не был нужен.** В этой версии `prepare_context` всегда собирает связи. Проверка «без графа» живёт в `eval_graph.py`: `facts = row['context']['facts'] if mode == 'graph_enriched' else []`. Python вычисляет только выбранную ветку. В старом варианте с `graph_context(...) if use_graph else []` выключение пропускало бы сам запрос связей. `*` в параметрах требует писать имя: `main(resume=path)`, а не `main(path)`. В старом `ask` это работало так же для `use_graph`.

### Почему параметры генерации фиксированы? Что делают `8192`, `1024`, `180`?

| Настройка | Простое объяснение |
|---|---|
| `temperature=0`, `seed=42` | Уменьшают вариативность, но не гарантируют одинаковый ответ. 42 не специальное число для этой задачи. |
| `num_ctx=8192` | Размер контекстного окна в токенах. Это не длина ответа. |
| `num_predict=1024` | Максимум выходных токенов в этой версии. В сохранённом прогоне был лимит 256; это не тот же запуск. Убрать параметр можно, но тогда применяется лимит Ollama или модели по умолчанию. |
| `timeout=180`, `stream=False` | Клиент ждёт целый HTTP-ответ, а не токены по одному. Таймаут — запас для локальной модели и не строгий общий дедлайн; к размеру контекста отношения не имеет. |

Это фиксированные значения прототипа, не измеренный оптимум. Один эксперимент использует одинаковые параметры в обоих режимах. Нельзя по старому прогону доказать, что `8192` обязательно нужно или всегда хватает меньшего окна.

### Что проверяют `raise_for_status` и `ValueError`?

**Первое проверяет HTTP, второе — содержание.** `raise_for_status()` бросает `HTTPError` при статусе `4xx/5xx`. HTTP может вернуть `200`, но `message.content` будет пуст или не строкой: тогда код бросает `ValueError`, потому что значение непригодно. Отсутствующий `message` / `content` вызовет `KeyError` раньше. Сигнал о пустом тексте не заменяет проверку качества или полноты ответа.

### Откуда берётся `done_reason` и зачем `get`? Для чего время и ключи Ollama?

**Ollama присылает JSON, `r.json()` превращает его в словарь `data`.** Если там `{'done_reason': 'length'}`, то `data.get('done_reason')` вернёт `'length'` и сравнение даст `True`. Если там `'stop'` — `False`; если ключа нет, `.get` вернёт `None`, тоже `False`. Это значит «Ollama сообщила об остановке по лимиту **выхода**», а не «мы проверили, что вход не обрезан».

`perf_counter()` — секундомер. Разница показаний до запроса и после разбора ответа даёт `wall_seconds`: длительность обращения к Ollama со стороны клиента. Не включает поиск статей. API возвращает только `answer`; для сводки эксперименту нужны `wall_seconds` и `truncated`. Вложенный словарь с токенами и внутренними длительностями Ollama убран из этой версии: ни ответу API, ни текущей сводке он не нужен.

## 5. Эксперимент: `eval_graph.py`

### Что такое абляция и какие поля у вопроса?

**Убираем один компонент и смотрим, что меняется.** Здесь неизменны вопрос, найденные статьи, аннотации и модель; меняется только блок связей. `expected_source_ids` — наши ожидаемые статьи для проверки поиска. `reference_facts` — подсказка оценщику, не модели. `expect_abstention` — пометка «данных недостаточно», например для вопроса о цене видеокарты; код не выставляет за неё оценку автоматически.

### Как работает `bool(set(case['expected_source_ids']) & found)`?

```python
expected = {'B'}            # проверяющий ждёт статью B
found = {'A', 'B', 'C'}      # что реально нашёл поиск
both = expected & found     # {'B'} — что есть в обоих множествах
hit = bool(both)             # True: осталось хотя бы что-то
```

Если B не нашли, `both` пуст и получится `False`. Если ожидаемой статьи нет вообще, внешний `if` ставит `None`: такой вопрос не входит в расчёт `hit@3`. Это оценка **поиска**, а не ответа.

### Как читать `run_answers`? Зачем `answers`, `review`, `comparison`, `comparison_notes`?

1. `enumerate` даёт номер и запись вопроса. Оператор `%` чередует порядок: без графа первым для одного вопроса, с графом первым для следующего. Это уменьшает перекос от прогрева, но не убирает его полностью. Вызовы последовательные.
2. `if mode in row['answers']: continue` пропускает уже сохранённый режим, **в том числе уже записанную ошибку**. Это продолжение прогона, не повтор упавших попыток.
3. Из сохранённого контекста выбираются одни и те же `papers`, для режима без графа — `[]` вместо связей. `build_prompt` получает только вопрос, статьи, факты. Поиск не повторяется.
4. `generate_answer` возвращает результат. `{'prompt': prompt, **generated}` кладёт под ключ режима промпт и поля результата. Если вызов упал, `except` пишет ошибку. `print(..., flush=True)` сразу выводит прогресс, на вычисления не влияет.
5. `save_report` сохраняет ход эксперимента после каждой попытки. `answers` заполняется кодом; `review` — незаполненная содержательная оценка одного ответа; `comparison` и `comparison_notes` — незаполненный итог и объяснение для пары.

### Что делает `citation_diagnostics`? Чем отличается от `summarize`?

**Диагностика проверяет принадлежность ссылок, сводка считает итог.** Если модели дали статьи A, B и C, а она сослалась на B и X, то `cited & allowed` найдёт B, а `cited - allowed` — X. Ссылка без версии разрешена для известной статьи; другая версия не принимается за ту же автоматически. Даже ссылка на B **не доказывает**, что B подтверждает фразу.

`summarize` считает `hit@3`, успешные ответы, ошибки, остановки по лимиту, ссылки на найденные/ненайденные статьи и среднее время успешных вызовов по режимам. Она не оценщик смысла. `save_report` сначала пишет временный `.tmp`, затем заменяет им отчёт: не оставляет половину JSON вместо последней сохранённой версии. Новый прогон по умолчанию пишет `graph_eval.json`, без даты в имени или метаданных отчёта.

### Какой отчёт показать? Что доказывают 4/4 и 1/4?

**Покажи [сохранённые ответы и таблицу](RESULTS_RU.md), новый запуск не нужен.** `4/4` — ожидаемый источник был в первых трёх у четырёх вопросов с ожидаемым источником. `1/4` — найденный URL был в одном из четырёх ответов в каждом режиме. Это не точность и не доказательство качества. На пяти знакомых вопросах явного выигрыша графа не увидели. Для уверенного вывода нужны новые вопросы, особенно по нескольким статьям, и проверка смысла фактов/ссылок людьми.
